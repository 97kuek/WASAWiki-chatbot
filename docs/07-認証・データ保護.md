# WASA Chat 認証・データ保護

Wikiログイン、セッション、利用回数、履歴、共有アシスタント、CORSと秘密情報の現行仕様を扱う。
採用理由は[01-設計方針.md](01-設計方針.md)、本番作業は
[04-デプロイ手順.md](04-デプロイ手順.md)を参照する。

## 認証方式

- 入力
  - 普段WASA Wikiで使う利用者名
  - 普段WASA Wikiで使うパスワード
- バックエンド
  - MediaWikiからログイントークンを取得する
  - 同じHTTPセッションで`action=clientlogin`へ中継する
  - `status: PASS`の場合だけ成功とする
  - Wikiが返した正規化済み利用者名を使う
- 対応しないもの
  - BotPasswords用の`action=login`
  - アプリ独自の共有パスワード
- タイムアウト
  - Wikiとの認証処理は20秒
- 失敗時
  - 認証失敗は300ms遅らせ、総当たり速度を落とす
  - Wiki接続失敗と認証情報の不一致を分けて返す

## パスワード

- 保存しない
- ログへ出さない
- Wikiへの検証後は保持しない
- Cookie、Firestore、チャット履歴へ入れない
- ログイン成否にかかわらずフロントの入力欄から消す
- 実装: `backend/internal/wiki/auth.go`と`backend/internal/server/server.go`

## セッションCookie

- 名前: `wasa_session`
- 内容
  - Base64URL化した利用者名
  - 有効期限
  - `SESSION_SECRET`を使ったHMAC-SHA256署名
- 有効期間: 30日
- 属性
  - `HttpOnly`
  - `Secure`
  - `SameSite=None`
  - `Partitioned`
  - `Path=/`
- ログアウト
  - Cookieを失効させる
  - 画面上の履歴を消す
  - Firestoreに同期済みの履歴は削除しない
- `SESSION_SECRET`
  - 本番では32文字以上の固定値を必須にする
  - 変更すると全員がログアウトする
  - Firestoreの利用者キーも変わり、既存の利用回数と履歴を参照できなくなる

## 認証が必要なAPI

- 認証不要
  - `POST /api/login`
  - `POST /api/logout`
  - `GET /api/session`
  - `GET /health`
- 認証必須
  - `POST /api/ask`
  - `GET /api/chats`
  - `PUT /api/chats/{id}`
  - `DELETE /api/chats/{id}`
  - `POST /api/feedback`
  - `GET /api/feedback`（`ADMIN_USERS`だけ）
  - `GET /api/assistants`
  - `POST /api/assistants`
  - `PUT /api/assistants/{id}`
  - `DELETE /api/assistants/{id}`

## CORS・CSRF・セキュリティヘッダー

- Cloud Runでは`ALLOW_ORIGIN`を必須にする
- 複数の許可元はカンマ区切りにする
- 許可外Originの状態変更リクエストを403で拒否する
- 許可元だけに次を返す
  - `Access-Control-Allow-Origin`
  - `Access-Control-Allow-Credentials: true`
- ローカル開発時だけlocalhost系ホストを同一扱いにする
- セキュリティヘッダー
  - `X-Frame-Options: DENY`
  - `X-Content-Type-Options: nosniff`
  - `Referrer-Policy: no-referrer`
  - CSPで外部スクリプト、`object`、フレーム埋め込み、外部画像を拒否する
- Cookieが`SameSite=None`のため、CORSヘッダーを返すだけでなくOrigin自体を検証する

## Firestore保存構造

- 利用者キー
  - 利用者名を平文のドキュメントIDにしない
  - 固定`SESSION_SECRET`で`state|利用者名`をHMAC-SHA256化する
- 利用回数
  - `users/{利用者HMAC}/usage/{日本時間の日付}`
  - `used`と更新時刻を保存する
- チャット履歴
  - `users/{利用者HMAC}/chats/{chatId}`
  - 最大30件
  - 質問、回答、出典、回答モード、回答時のアシスタントID・名前、段階別所要時間を含む
- 共有アシスタント
  - `assistants/{assistantId}`
  - 全員で共有するため`users`配下へ置かない
  - 作成者名は責任の表示に必要なため平文で保存・表示する
- 利用者フィードバック
  - `feedback/{feedbackId}`
  - 報告者は利用者名ではなくHMACキーで保存する
  - 回答評価には質問・回答・出典・段階別所要時間を含む
  - 画面全体の報告には質問・回答を含めない
  - 管理者APIは報告者HMACキーを返さない
  - Firestoreへの保存が先、管理者メールへの通知が後。メール障害で保存を取り消さない
  - メール本文へ利用者名と報告者HMACキーを入れない
- ブラウザ
  - Firestoreへ直接接続しない
  - Wiki認証済みCookieを検証するGo APIだけを通す

## 利用回数

- 既定: 利用者1人あたり日本時間で1日30質問
- `DAILY_LIMIT`で変更できる
- Firestoreトランザクションで質問前に1回を確保する
- 同時送信、別端末、Cookie削除、Cloud Run再起動でも上限を共有する
- 次の失敗では確保分を返却する
  - Geminiの利用制限
  - LLM通信障害
  - 回答生成失敗
- アシスタント取得失敗や不正入力は確保前に止める

## LLMへ送るデータ

- 送るもの
  - `facts.md`を含む目次
  - 選択したWiki・公式サイト本文
  - 現在の質問
  - 最大2往復の直近会話
  - 選択した共有アシスタントの指示
- 送らないもの
  - Wikiパスワード
  - Firestoreの全履歴
  - 利用者名を含むセッションCookie
  - `.env`
- Gemini無料枠
  - 非公開Wiki本文を送る組織承認が必要
  - 2026-08-08のWASA会議で代表・PMが承認した
  - 本番では`GEMINI_PAID_TIER=true`または`GEMINI_FREE_TIER_APPROVED=true`が無ければ起動しない

## リポジトリとデプロイ

- コミットしない
  - `.env`
  - `dump/`
  - `data/`
  - `eval/golden.json`
- 公開フロントへ置かない
  - Wiki本文
  - 索引
  - APIキー
  - セッション署名鍵
- Cloud Run
  - `SESSION_SECRET`をSecret Managerから渡す
  - `GEMINI_API_KEY`をSecret Managerから渡す
  - `FIRESTORE_PROJECT_ID`と`ALLOW_ORIGIN`を必須にする
- 詳細: [04-デプロイ手順.md](04-デプロイ手順.md)

## 確認

```bash
cd backend
GOCACHE=/private/tmp/wasa-go-cache go test ./...

LIVE_WIKI_TEST=1 GOCACHE=/private/tmp/wasa-go-cache \
  go test ./internal/wiki -run '^TestLoginSuccess$'
```

- 通常テストは模擬Wikiを使い、外部へ接続しない
- 実Wikiテストの秘密値は`.env`だけに置く
- 認証方式や個人情報のマスキング範囲を変える場合は、人間の判断を先に得る
