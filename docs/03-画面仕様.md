# WASA Chat 画面仕様

この文書は、利用者が実際に触る画面が、いまどう動いているのかをまとめたものです。

「なぜこの設計にしたか」ではなく「**いまこう動いている**」を書く場所だと考えてください。
画面を変えたときは、この文書も一緒に直してもらえると助かります。

なお、ログインやCookie、保存先の話は[07-認証・データ保護.md](07-認証・データ保護.md)、
AIがどういう規則で回答しているかは[05-システムプロンプト.md](05-システムプロンプト.md)と
[06-決定的ルール.md](06-決定的ルール.md)にあります。

## チャット画面

WASA Chatの中心になる画面です。

PCとスマホでは画面の広さが全然違うので、同じ部品を同じように並べると
どちらかが必ず使いにくくなります。そこで、広い画面と狭い画面で置き方を変えています。

**PCでの表示**

- 左にロゴ、新しいチャット、アシスタント、履歴、利用者情報を置きます
- 右に会話本文を置き、入力欄を下部へ固定します
- 履歴欄は折りたためます
- 履歴のスクロールつまみは、サイドバー上で見失わないよう濃い色にしています

**狭い画面での表示**

- 履歴欄は初期状態で閉じています
- 開いた履歴欄は会話の上へ重ね、背景をタップしても閉じられます
- 入力欄と通知が重ならないようにしています

**初期表示**

まだ何も質問していない状態では、何ができるアプリなのかが分からないと手が止まってしまいます。
そこで最初の画面では次を見せています。

- 「引き継ぎ資料を、会話で探す」と表示します
- Wikiと公式サイトを横断し、参照した資料を示すことを説明します
- 質問例を6件表示します

**質問の入力**

- 500文字以内とします
- `Enter`で送信し、`Shift + Enter`で改行します
- 送信した直後から、右寄せの吹き出しとして画面に残します
- 回答生成中は二重送信を防ぎます

**回答の表示**

回答は一気に出てくるわけではなく、資料を探してから文章を作るという段階を踏みます。
その間ずっと画面が固まって見えると不安になるので、いま何をしているかを出しています。

- 回答者のアイコン・名前・回答モードを表示します
- ページ選択、資料読込、回答生成、API待機の進捗を表示します
- MarkdownとTeXを表示します
- 出典は、Wikiと公式サイトを区別したカードにします
- 回答はSSE（サーバーから少しずつ送る仕組み）で逐次表示します
- 完了後に👍／👎を表示し、1タップで評価を保存します
- 評価理由と補足文は任意です

## アシスタント切り替え

アシスタントとは、口調や参照範囲を決めた設定のことです。

ここで一番大事なのは、**アシスタントを切り替えると新しいチャットが始まる**という点です。
一見おせっかいな挙動に見えますが、これには理由があります。

アシスタントごとに、一般知識を使ってよいか、どの資料を参照するか、どんな口調で答えるかが
違います。同じ履歴の中でこれらを混ぜてしまうと、**過去の回答をどの規則で読めばいいのか
誰にも判別できなくなります**。そこで、切り替えたら会話も分けることにしました。

**アシスタントを切り替えた場合**

- 選んだアシスタントを端末へ保存します
- アシスタント一覧からチャット画面へ戻ります
- 既存の会話へ継ぎ足さず、新しいチャットを開きます
- 画面上部の通知で、切り替えたことと新しいチャットを作ったことを伝えます

**同じアシスタントをもう一度選んだ場合**

- 新しいチャットを増やさず、現在のチャットへ戻ります
- 空のチャットが無駄に増えていくのを防ぐためです

**回答生成中の場合**

- 規則と参照範囲が途中で変わらないよう、切り替えを拒否します

なお、履歴には各回答時の`assistantId`と`assistantName`も残しているので、
あとから「この回答はどのアシスタントのものか」を追いかけられます。

## アシスタント一覧・編集

アシスタントは、**ログインしていれば誰でも作れて、全員が使えます。**

内容の審査はしていません。その代わり、まずいことが起きないように構造で縛っています
（参照範囲は狭める指定しかできない、出典はサーバーが組み立てる、作成者名を必ず出す、など）。
詳しくは[06-決定的ルール.md](06-決定的ルール.md)にあります。

**一覧の表示**

- 汎用を先頭に置きます
- 共有アシスタントは、アイコン、名前、説明、作成者、参照範囲を表示します
- お気に入り、名前順、作成者順で並べ替えられます
- お気に入りと並び順だけを`localStorage`（ブラウザ内の保存領域）へ保存します

**作成**

- ログイン済みの全員が作成できます
- 名前、説明、指示、参照出所、参照区分、任意の画像を設定できます
- 画像は位置を調整して128pxの正方形へ焼き込んでから送ります

**編集と削除**

- 作成者本人と`ADMIN_USERS`にだけ表示します
- 他人の設定は直接編集できません。複製して、自分の設定として直す形になります

**回答上の位置づけ**

ここは誤解されやすいので明記しておきます。

**アシスタントは、別の高精度なモデルではありません。** 使っているモデルは汎用と同じです。
違うのは参照範囲の絞り込み、一般知識を使ってよいかどうか、回答形式・口調だけです。
「専門アシスタントの方が賢い」という説明はしないでください（そもそも精度差は未測定です）。

## チャット履歴

過去のやりとりは、Wiki利用者ごとにFirestoreへ保存しています。

端末のブラウザではなくサーバー側に置いているので、**別のパソコンやスマホでログインしても
同じ履歴が見られます。** ただし無制限に貯めると費用も表示も重くなるため、上限を設けています。

- Wiki利用者ごとに最大30チャットをFirestoreへ保存します
- 最初の質問の先頭28文字を初期タイトルにします
- 追質問を行った履歴は先頭へ移動します

表示は次のように分けています。

- ピン留め
- 今日
- 昨日
- 過去7日間
- `YYYY年M月`

各履歴では、ピン留め・解除、タイトル変更、端末の共有機能またはクリップボードによる共有、
個別削除ができます。共有する前には、非公開Wikiの内容を含む可能性があることを確認しています。

なお「すべて削除」は表示していません。まとめて消す操作は取り消しがきかないためです。

追質問については、**完了済みの直近2往復だけをAPIへ送り、全履歴は送りません。**
これは費用の問題です。全部送ると会話が長くなるほど毎回の費用が増えていきます。
また、アシスタントを切り替えたときは追質問にせず、新しい履歴を始めます。

## 回答モード

回答の「じっくり度合い」を選べるようにしています。

以前は4段階から選ぶ形でしたが、質問する前に速度を細かく決めさせるのは、
利用者にとって余計な判断でした。そこで画面上は2択にして、細かい段階は内部で自動判定しています。

- 入力欄の上に「自動・じっくり」の2択を置きます
- 「高速・標準」は自動判定内部の段階であり、通常画面では選ばせません
- 選択を`localStorage`へ保存します
- 旧画面で保存された「高速・標準」は「自動」へ移行します
- 生のモデル名やthinking値を通常画面へ出しません
- 回答欄には、利用者が指定したモードを残します
- 自動で内部判定された高速・標準の段階は、通常画面へ表示しません
- APIが受け付ける値は`auto / fast / standard / deep`だけです

自動判定は、質問の中身を見てコード側で決めています。LLMを追加で呼んではいません。

- 比較、変遷、歴代、理由などを含む質問は「じっくり」
- 型番、日付、人物の一点確認は「高速」
- その他は「標準」

段階ごとに使うモデルは、サーバー側の許可リストから選びます。
**ブラウザからモデルIDを直接指定させることはありません。**

## 通知と読込表示

一時的なお知らせ（保存した、削除した、アシスタントを切り替えた、など）の出し方です。

画面下部に出すと入力欄と重なってしまい、スマホでは特に邪魔になります。そのため上から出しています。

- 画面下部には出しません
- 画面上部中央から現れ、時間経過後に上へ戻って消えます
- チャット本文と入力欄を覆いません

回答待ちの表示にもこだわりがあります。

- 主翼・胴体・尾翼の分かる機体が、航跡を引いて旋回するアニメーションを表示します
- 初期読込では大きな旋回表示、回答欄では小さな進捗表示として、同じ意匠を使います
- OSの`prefers-reduced-motion`（動きを減らす設定）が有効なら、動きを抑えます

右上のメニュー（改善、お知らせ、プロフィール）は、同時に1つだけ開きます。
別のボタンを押した場合は、開いていた内容を閉じて、押した内容へ切り替えます。

## フィードバック

利用者から「役に立ったか」「使いにくいか」を受け取るための導線です。

自動評価だけでは、実際に使った人がどう感じたかは分かりません。かといって長い文章を
必須にすると誰も送ってくれないので、**1タップでも送れて、理由や補足は任意**という形にしています。

- 右上にあった、情報量が重複していた「WASA」表示を削除しました
- 同じ位置に「改善を送る」を置いています
- 説明は「匿名で管理者にフィードバックを送れます」だけを表示します

送信のタイミングは、報告の種類によって変えています。

- **画面全体の報告**は、分類を1つ選んだうえで、明示的な「送信する」を押した時点で送信します
  - 分類の選択だけでは送信しません。押した瞬間に送ってしまうと、内容を見直したり
    補足を書いたりする前に保存されてしまい、取り消せないためです
- **回答評価**は、👍／👎を押した時点で送信します
  - こちらは1タップで完結させたいので、押した時点で保存します
- 理由チップと500文字以内の補足は、どちらも任意です

スマホではポップアップを画面幅へ収め、分類と送信を44px以上のタップ領域で縦に並べます。
また、管理者だけが最近の報告と件数を同じ画面で確認できます。

詳しくは[08-評価・フィードバック.md](08-評価・フィードバック.md)にあります。

## アシスタント一覧の密度

一覧に情報を詰めすぎると探しにくく、余白を取りすぎると1画面に入りません。

- 汎用アシスタントは、ロボット記号ではなくWASA Chatのマークを使います
- PCでは、タイトル、説明、件数、並べ替え、新規作成を同じ1行へ置きます
- 狭い画面では説明を省略し、並べ替えと新規作成を同じ操作行へ置きます

## Markdown・TeX・リンク

回答には数式や表が出てくるため、そのまま文字で出すと読めません。
そこでMarkdownとTeXを解釈して表示しています。

**対応しているMarkdown**

見出し、箇条書き、番号付きリスト、表、引用、水平線、強調、コードです。

**対応しているTeX**

`$ ... $`、`\( ... \)`、`$$ ... $$`、`\[ ... \]`の4種類です。

**安全性の扱い**

ここは手を抜くと危ない部分です。回答文はモデルが生成したものなので、
そのままHTMLとして表示すると、意図しないものが動く余地が生まれます。

- 生HTMLをエスケープします
- リンクはHTTP / HTTPSだけを許可します
- KaTeXは`trust: false`とします
- コード記法内の`$`を数式として解釈しません

## 実装対応

画面を直すときに、どのファイルを見ればよいかの対応表です。

| ファイル | 担当している範囲 |
|---|---|
| `web/src/App.tsx` | 画面、履歴、アシスタント、通知、送信、SSE更新 |
| `web/src/styles.css` | レイアウト、レスポンシブ表示、通知と読込アニメーション |
| `web/src/api.ts` | ログイン、セッション、履歴、アシスタント、SSE通信 |
| `web/src/markdown.tsx` | MarkdownとKaTeXの安全な表示 |
| `web/public/announcements.json` | お知らせ本文 |

## 確認

画面を直したら、まずビルドが通ることを確認します。

```bash
cd web
npm run build
```

そのうえで、実際に触って次を確認してください。特に上の3つは、
過去に壊れたことがある挙動です。

- アシスタントを変更すると、空の新規チャットへ移る
- 同じアシスタントを再選択しても、履歴が増えない
- 回答中は切り替えられない
- 通知が入力欄と重ならず、上から現れて消える
- PCと狭い画面の両方で、履歴・入力欄・通知が重ならない
