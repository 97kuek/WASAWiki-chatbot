# WASA Chat 引き継ぎガイド

この文書は、WASA Chatの引き継ぎを行うために書いた文書です。最初から全部を理解する必要はありません。

まずこのページを読み、作業に関係する文書だけを開いてください。

## 最初に知っておく言葉

- **フロントエンド**: 利用者がブラウザで見る画面です。`web/`にあります。
- **バックエンド**: ログイン、資料検索、AIへの質問、保存を行うサーバーです。`backend/`にあります。
- **索引（インデックス）**: Wikiや公式サイトを、質問から探しやすい形へ整理したファイルです。
- **チャンク**: 長い資料を見出しごとに分けた、検索の単位です。
- **Firestore**: Google Cloud上の保存場所です。履歴、利用回数、フィードバックを保存します。
- **SMTP**: WASA Chatからメール送信サービスへ、通知メールを渡す方法です。
- **デプロイ**: 手元で直したものを、本番で使える状態にする作業です。

## 普段の運用

- Wikiや公式サイトに変更があるか確認する

```bash
python check_updates.py
```

- 変更が見つかったら、取得・索引作成・検索検査をまとめて行う

```bash
python rebuild.py
```

- `rebuild.py`は自動で本番公開しません
  - 非公開Wikiの内容が正しく取得できたか、人が差分を確認するためです
  - 確認後の公開手順は[04-デプロイ手順.md](04-デプロイ手順.md)にあります
- 利用者から届いたフィードバックは2か所で確認できます
  - 管理者でログインした画面の「改善を送る」
  - `FEEDBACK_EMAIL_TO`に設定したメールアドレス
  - メール送信に失敗しても、内容はFirestoreに残ります

## 機能を変えるときの確認先

- プロンプトを変える
  - `docs/05-システムプロンプト.md`の責務と入力順を確認する
  - 本番Goと測定用Pythonの共通部分を両方更新する
  - アシスタント固有のsystem規則・範囲制限は本番Goだけにあるため、差を消したつもりにしない
  - ゴールデンデータ全体で推論し、ミス・指摘漏れ・過剰検知を分類する
- 検索やマスキングを変える
  - `docs/06-決定的ルール.md`と`build_index.py`を確認する
  - 数字を測り、`docs/02-測定結果.md`へ再現コマンドと結果を残す
- ログイン・Cookie・Firestoreを変える
  - `docs/07-認証・データ保護.md`を確認する
  - 認証方式や個人情報の扱いを技術判断だけで変えず、人間へ確認する
- 画面を変える
  - `docs/03-画面仕様.md`を確認する
  - `npm run build`と狭い画面での重なりを確認する
- 本番設定を変える
  - `docs/04-デプロイ手順.md`を確認する
  - `min-instances=0`と初期運用の`max-instances=1`を維持する

## 最低限の検証

```bash
cd backend
GOCACHE=/private/tmp/wasa-go-cache go test ./...

cd ../web
npm run build

cd ..
python -m py_compile rag/pipeline.py eval/response_mode_eval.py
```

- 実Wiki認証は通常の単体テストでは外部通信しない
- 実Wikiで確認する場合だけ、秘密値を`.env`へ置いて`LIVE_WIKI_TEST=1`を付ける
- 非公開の`dump/`、`data/`、`.env`、`eval/golden.json`をコミットしない
