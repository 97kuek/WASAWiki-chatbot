コードと画面の対応を確認するための現行仕様。設計判断の根拠は
[01-設計方針.md](01-設計方針.md)、精度の数字は [02-測定結果.md](02-測定結果.md) を参照する。

## チャット画面

- PC
  - 左側にWASA Chatのロゴ、新しいチャット、チャット履歴、利用者情報を置く
  - 右側に会話本文を置く
  - 入力欄は会話領域の下部に固定する
- ヘッダー
  - 右側にWASA、通知、利用者アイコンを置く
  - ベルを押すとお知らせを開き、未読がある場合だけ青い丸を付ける
  - 利用者アイコンを押すと、利用者名、WASA Wikiへのリンク、ログアウトを開く
  - どちらのメニューも外側または `Escape` キーで閉じる
  - サポートリンクは案内先が決まるまで表示しない
- 初期表示
  - 「引き継ぎ資料を、会話で探す」と表示する
  - 説明は「部内Wikiと公式サイトを横断して回答し、参照した資料を示します。」の一文だけにする
  - 質問例は6件に絞る
- 履歴欄
  - ヘッダーのメニューボタンまたは履歴欄内の閉じるボタンで開閉する
  - 狭い画面では会話の上へ重ねて表示し、背景を押して閉じられる
  - 選択中の履歴は背景だけで示し、左側の青い線は表示しない
- スマートフォン
  - 履歴欄を初期状態では閉じる
  - 会話本文と入力欄の幅を画面に合わせる
- 質問
  - 送信直後に右寄せの吹き出しとして表示する
  - 回答の生成中も質問を画面に残す
- 回答
  - WASAロゴの横に表示する
  - ページ選定などの進捗を回答前に表示する
  - 出典はWikiと公式サイトを区別したリンクカードで表示する
- 通信
  - 質問はPOSTのJSON本文で送る
  - 質問をURLへ入れず、一般的なアクセスログに文面を残さない
  - 回答はSSEで逐次表示する
- 入力
  - 質問入力と送信を小さな1つの枠にまとめる
  - 画面下部へ固定する
  - 会話領域との境界線は置かず、白いグラデーションで自然につなぐ
  - 500文字を上限とする
  - `Enter` で送信する
  - `Shift + Enter` で改行する
  - 回答生成中は二重送信を防ぐ

実装:

- `web/src/App.tsx`: 画面構造、履歴、送信、ストリーミング更新
- `web/src/styles.css`: PC / スマートフォンのレイアウトと見た目
- `web/src/api.ts`: ログイン、セッション、SSE受信

## チャット履歴

- 履歴はWiki利用者ごとにFirestoreへ保存し、ログインした端末間で共有する
- Firestoreの利用者ドキュメントIDは、固定した`SESSION_SECRET`による利用者名のHMAC値にする
- ブラウザからFirestoreへ直接接続せず、Wiki認証済みCookieを検証するGo APIだけを通す
- 最大30チャットまで保持する
- 最初の質問の先頭28文字を履歴タイトルにする
- 過去のチャットへ追質問すると履歴の先頭へ移動する
- 表示を次の単位に分ける
  - ピン留め
  - 今日
  - 昨日
  - 過去7日間
  - `YYYY年M月`
- 履歴へカーソルを合わせるかフォーカスすると3点メニューを表示する
- 3点メニューから次の操作を行う
  - ピン留め、ピン留め解除
  - タイトル変更
  - 端末の共有機能またはクリップボードによる共有
  - 個別削除
- 共有前に、非公開Wikiの内容が含まれる可能性を確認する
- 「すべて削除」は表示しない
- 利用者が各履歴の「削除」を押したときだけ、対応するFirestoreドキュメントを削除する
- ログアウトやタブを閉じたときは端末上の表示だけを消し、Firestoreの履歴は残す
- Firestore導入前の`sessionStorage`履歴は、初回ログイン時に新しい内容を優先して移行し、成功後に端末側から削除する
- 非公開Wikiの内容を公開フロントや`localStorage`へ恒久保存しない

## MarkdownとTeX

- Markdown
  - 見出し
  - 箇条書き、番号付きリスト
  - 表
  - 引用、水平線
  - 強調、コード、HTTP / HTTPSリンク
- TeX
  - インライン: `$ ... $`、`\( ... \)`
  - ブロック: `$$ ... $$`、`\[ ... \]`
  - 複数行のブロック数式
- 安全性
  - Markdown内の生HTMLは最初にエスケープする
  - リンクはHTTP / HTTPSだけを許可する
  - KaTeXは `trust: false` とし、HTMLを生成する危険な命令を許可しない
  - コード記法の中にある `$` は数式として解釈しない

実装:

- `web/src/markdown.tsx`: Markdownの安全な変換とKaTeX描画
- `web/src/styles.css`: 本文、表、数式の表示と横スクロール

## 認証

- 入力するもの
  - 普段WASA Wikiで使う利用者名
  - 普段WASA Wikiで使うパスワード
- 認証経路
  - バックエンドがMediaWikiの `action=clientlogin` へ中継する
  - `status: PASS` の場合だけ署名付きCookieを発行する
  - BotPasswords用の `action=login` は扱わない
- パスワード
  - 保存しない
  - ログへ出さない
  - Wikiでの確認後は保持しない
  - ログイン成否にかかわらずフロントの入力欄から消す
  - 目のアイコンで入力内容の表示と非表示を切り替える
- ログイン画面
  - 「WASA Wikiと同じ利用者名・パスワードでログイン」と表示する
  - 「パスワードはWikiで本人確認をするためだけに使用します」を小さい文字で1行表示する
  - 「WASA 鳥人間プロジェクト」という補助見出しは表示しない
  - フォーカスや選択状態のアクセント色は添付見本に合わせた青 `#1717e8` に統一する
- Cookie
  - セッションCookieには利用者名と有効期限だけを載せる
  - 旧版の使用回数CookieはFirestoreへの初回移行だけに使い、移行後に削除する
  - CookieはHMACで署名する
  - `HttpOnly`、`Secure`、`SameSite=None`、`Partitioned`を付ける
  - Cloudflare PagesとCloud Runが別サイトでも、対応ブラウザではトップレベルサイト単位にCookieを分離する
- CSRF / CORS
  - Cloud Runでは `ALLOW_ORIGIN` を必須にする
  - ブラウザの `Origin` が `ALLOW_ORIGIN` と一致しないリクエストを403で拒否する
  - 複数の許可元はカンマ区切りで指定する
  - ローカル開発時だけ、同じスキーム・ポートの`localhost`、`127.0.0.1`、`::1`を同一扱いにする
  - 許可元だけに `Access-Control-Allow-Origin` と資格情報許可を返す
  - Cloud RunとCloudflare Pagesの両方で、フレーム埋め込み、外部スクリプト、`object`をセキュリティヘッダーにより拒否する
- ログアウト
  - Cookieを失効させる
  - 現在の画面からチャット履歴を消すが、端末間同期用のFirestore履歴は保持する

## 質問回数の上限

- 利用者単位
  - 既定値は利用者1人あたり1日30回
  - 残り回数は左下の利用者情報にだけ「本日はあと○回」と表示する
  - `DAILY_LIMIT` 環境変数で変更できる
  - 日本時間の0時に日付を切り替える
  - Gemini側の制限や通信障害で失敗した質問は回数を返却する
  - Firestoreトランザクションで質問開始時に回数を確保し、同時送信でも上限を超えないようにする
  - Gemini側の制限や通信障害で失敗した場合は、確保した回数をFirestoreへ返却する
  - 利用者名は保存せず、固定した`SESSION_SECRET`によるHMAC値、日本時間の日付、使用回数だけを保存する
  - Cookie削除、別端末、Cloud Run再起動をまたいでも同じ利用者の回数を引き継ぐ
  - 旧版の署名付き使用回数Cookieは初回セッション取得時にFirestoreへ移行して削除する
- Geminiプロジェクト全体
  - WASAで1つのGoogle CloudプロジェクトとAPIキーを管理し、APIキーはサーバー側だけに置く
  - GeminiのRPM・TPM・RPDはAPIキー単位ではなくGoogle Cloudプロジェクト単位で数えられる
  - 1質問で通常2回、長い資料では3回Gemini APIを呼ぶ
  - 1つのバックエンドインスタンス内で全利用者の生成処理を直列化する
  - 初期運用はCloud Runの `max-instances=1` とし、複数台へ増やす前に共有レート制限を設計する
  - `GEMINI_MIN_INTERVAL` の既定値4秒以上をリクエスト間に空ける
  - 短時間の429、503、通信失敗は `GEMINI_MAX_RETRIES` の既定値2回まで追加試行する
  - 日次上限の429は再試行しない
  - `Retry-After` または `retryDelay` があれば待機時間に使い、1回の待機は最大60秒にする
  - 短時間の429なら1〜15分Gemini呼び出しを停止する
  - 日次上限の429ならGoogle側の太平洋時間0時までGemini呼び出しを停止する
  - Google側の日次上限は太平洋時間、利用者単位の上限は日本時間で別々に切り替わる
  - 実際の上限値はモデルと利用枠で変わるため、固定値を仕様にせずGoogle AI Studioで確認する
  - 参考: [Gemini APIのレート制限](https://ai.google.dev/gemini-api/docs/rate-limits)
- 無料枠のデータ
  - 無料枠は送信内容がGoogleの製品改善に使われる
  - 2026-08-08のWASA会議で、代表・PMが氏名・役職などを残した非公開Wiki本文の無料枠への送信を許可した
  - Cloud Runでは`GEMINI_PAID_TIER=true`または`GEMINI_FREE_TIER_APPROVED=true`を設定しない限り起動しない
  - 参考: [Gemini Developer APIの料金とデータ利用](https://ai.google.dev/gemini-api/docs/pricing)
- 表示更新
  - 質問完了後にセッション情報を取り直し、サーバー側の残り回数と一致させる
  - 短時間の上限では「一時的な利用制限がかかっています」と回答欄へ表示する
  - 日次上限では「本日の無料枠を使い切りました」と回答欄へ表示する
  - 利用者単位の上限では「本日の質問上限に達しました」と回答欄へ表示する
  - 送信間隔の調整中と短時間の再試行中は、待機理由と残り時間を進捗欄へ表示する
  - 429で処理を停止した場合は、回答欄へ再開までの時間と時刻を表示する
  - `Retry-After` または `retryDelay` が無い短時間上限は、1〜15分の安全側の見積もりを表示する

## お知らせと利用者メニュー

- お知らせ
  - `web/public/announcements.json` の配列を表示する
  - 空配列なら「現在のお知らせはありません」と表示する
  - 各要素は `id`、`title`、`body`、`date` を文字列で持つ
  - 既読状態はお知らせIDだけを `localStorage` に保存する
  - 非公開Wiki本文やチャット内容は保存しない
- 利用者メニュー
  - 利用者名を表示する
  - `VITE_WIKI_URL` のWASA Wikiを別タブで開く
  - ログアウトできる
  - 残り回数は重複させず、左下だけに表示する

実装:

- `backend/internal/wiki/auth.go`: MediaWiki認証
- `backend/internal/llm/http_clients.go`: Geminiの直列化、間隔制御、再試行、一時停止
- `backend/internal/server/server.go`: Cookie、認証必須API、履歴API、利用回数の確保と失敗時の返却
- `backend/internal/state/`: Firestoreとローカル開発用メモリの共有状態実装
- `web/src/App.tsx`: ログイン、履歴同期、残り回数の再取得、お知らせ、利用者メニュー
- `web/public/announcements.json`: 配信するお知らせ

## 確認コマンド

```bash
cd backend
go test ./...

cd ../web
npm run build
```

- 実Wikiを使う認証テストだけは `.env` の `WIKI_API`、`WIKI_USER`、`WIKI_PASS` を使う
- `LIVE_WIKI_TEST=1` がなければ実Wikiへの接続をスキップし、ローカルの模擬Wikiに対するテストだけを行う
- 実Wikiの確認はテスト内で `.env` を解析するため、値に空白があってもシェル命令として扱わない

```bash
cd backend
LIVE_WIKI_TEST=1 go test ./internal/wiki -run '^TestLoginSuccess$'
```
