# WASA Chat 決定的ルール

モデルの判断に任せず、コードで同じ結果を保証する規則をまとめる。プロンプトによる誘導や
作成者名の表示は強さが違うため、この文書では明確に分ける。

## 保証の強さ

- コードの保証
  - 入力上限と許可値
  - 参照範囲外ページの除外
  - 出典カードの組み立て
  - 実在タイトル・節IDの照合
  - 型番の正規化一致
  - 履歴件数と会話文脈の上限
- 緩和策
  - system規則による資料外補完・指示上書きの抑制
  - モデルが必ず従う保証ではない
- 社会的な抑止
  - アシスタント作成者名の表示
  - 他人の設定を直接編集させず複製だけにする

## 索引生成

- 正本: `build_index.py`
- 対象
  - MediaWiki標準名前空間の実記事
  - 公式サイトの固定ページと投稿
  - リダイレクトは本文にせず、転送先の別名として保持する
- 除外
  - 20字未満だけを実質的に空としてチャンク化しない
  - 120字未満はスタブ表示にするが、20字以上なら検索対象から外さない
- チャンク
  - 目標1,200字
  - 最大2,500字
  - 末尾が200字未満なら、最大値を超えない範囲で直前へ吸収する
  - 最上位見出しをまたがない
  - パンくずはチャンク内全節の共通接頭辞から作る
- 個人情報
  - wikitextのパース前にマスキングする
  - 生年月日を`［生年月日］`へ置き換える
  - 個人用メールを置き換える
  - 業務上の申請先・共有連絡先は残す
  - 氏名、役職、区分は検索要件があるため残す
- 区分
  - `TEAM_RULES`を正本とする
  - 代まとめ・人物ページを先に弾く
  - タイトルを優先し、無ければ本文冒頭400字で補う
- 年代
  - `last_edited`を本文の鮮度として使わない
  - 本文の西暦と20〜49代をチャンク単位で抽出する
  - `N代 = 1984 + N年大会`で西暦へ対応させる

## ページ・節の選択

- 正本: `backend/internal/pipeline/pipeline.go`
- ページ
  - モデル候補は最大4件
  - `index.Resolve`で実在タイトルまたは一意な別名だけへ解決する
  - 架空タイトル、曖昧な部分一致、節名を落とす
  - 質問中の実在タイトルを、型番候補と合わせて最大2件までモデル候補より先に加える
  - `40th`と`40代`は同一視し、分野名と世代の両方が合うページを優先する
  - 3文字以下の英数字タイトルは単語完全一致だけを認める
  - 0件ならタイトル・パンくずの文字bigramで保険検索する
- 型番
  - 英字で始まり数字を含む4文字以上だけを型番候補にする
  - 大文字小文字、ハイフン、アンダースコアの差を無視する
  - ページ本文の完全一致上位2件をモデル候補より先に加える
  - 節選択でも完全一致した節を優先して統合する
- 節
  - 選択本文が12,000字以内なら全節を渡す
  - 超える場合だけモデルで最大8節へ絞る
  - モデルが返したIDは、選択済みページに実在するものだけを受け付ける

## アシスタントの参照範囲

- 正本
  - 検証: `backend/internal/assistant/assistant.go`
  - 除外: `backend/internal/pipeline/pipeline.go`の`inScope`と`scopedTOC`
  - 解決: `backend/internal/server/server.go`の`lookupAssistant`
- 参照範囲は狭める指定だけを持つ
  - 出所: Wiki / 公式サイト
  - 区分: 許可リスト内の1区分
- ページ選択、実在タイトル候補、保険検索、型番検索のすべてで範囲外を落とす
- 公式サイト限定時
  - 全体目次ではなく`SiteTOC`を渡す
  - 限定目次が作れなければ、全体目次へ広げず目次なしにする
- アシスタントIDの取得失敗時
  - 汎用へ戻して続行しない
  - 質問回数を消費する前に409で停止する
- 出典
  - 選択済み索引からサーバーが組み立てる
  - SSEの`pages`イベントで送り、モデルの文章から抽出しない

## アシスタント保存値

- 名前: 1〜40文字
- 説明: 最大120文字
- 指示: 1〜1,500文字
- ID: 小文字英数字とハイフンで最大64文字
- アイコン
  - PNG / JPEG / WebPのdata URIだけ
  - 最大96KiB
  - SVGと外部URLを拒否する
- 権限
  - 作成: ログイン済みの全員
  - 編集・削除: 作成者本人と`ADMIN_USERS`
  - 他人のものは複製だけ
  - ID、作成者、作成日時は編集で変更しない

## API入力と履歴

- 正本: `backend/internal/server/server.go`
- 質問
  - JSON本文で送る
  - URLへ入れない
  - 1〜500文字
  - リクエスト本文は最大32KiB
- 回答モード
  - `auto / fast / standard / deep`だけ
  - 空文字は旧画面との互換のため`auto`
  - 通常画面で選べるのは`auto / deep`だけ。`fast / standard`は自動判定と旧画面の互換用
- 会話文脈
  - 最大2往復
  - 各質問は1〜500文字
  - 各回答は1〜2,000文字
  - 過去回答を今回の根拠として扱わない
- 履歴
  - 利用者ごとに最大30チャット
  - 保存リクエストは最大1MiB
  - 上限超過時は更新日時が古い履歴から削除する
- アシスタント保存リクエスト
  - 最大256KiB

## 回答モードの決定

- 正本: `backend/internal/pipeline/pipeline.go`の`resolveResponseMode`
- 利用者が明示した場合
  - その段階を使う
- 自動
  - 比較、差異、変遷、歴代、全体、網羅、理由、背景などを`deep`
  - 型番、いつ、何年、誰を`fast`
  - その他を`standard`
- モデル選択
  - サーバー環境変数の許可リストだけを使う
  - 未設定の段階は既定モデルへ戻す
  - 実測で改善を確認するまで強いモデルを既定にしない

## 変更時の確認

- 先に再現できる失敗例を用意する
- 実データにevidenceが存在することを照合する
- Python測定経路とGo本番経路の共通規則を両方更新する
- 数字を`docs/02-測定結果.md`へ残す
- 次を実行する

```bash
python eval/retrieval_eval.py

cd backend
GOCACHE=/private/tmp/wasa-go-cache go test ./...
```
